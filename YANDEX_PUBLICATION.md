# Проверка перед публикацией в Яндекс Играх

Проверяется ветка `cursor/conveyor-prototype-b9e9`. Локальный аудит и SDK-заглушка не заменяют проверку загруженной игры в консоли Яндекса и решение модерации.

## Что подготовлено в коде

- Подключение платформенного `/sdk.js`, инициализация SDK до запуска игры, `LoadingAPI.ready()` после первого отрисованного экрана. `GameplayAPI.start()` вызывается после явного старта игры; пауза и конец партии останавливают gameplay.
- Подписки на `game_api_pause` / `game_api_resume`; приостановка игры при потере видимости/фокуса. Платформенный resume возобновляет только платформенную паузу и не снимает ручную паузу или открытое меню. Оба порядка resume/onClose рекламы обработаны.
- Во время рекламы игра приостановлена и звук выключен. Награда выдаётся только по `onRewarded`; ошибки/закрытие без награды её не выдают. Просмотр добровольный, кнопки обозначают рекламу и размер награды.
- Параметр `mockAds=1` работает только в режиме разработки Vite. В production он не включает фиктивные объявления и награды.
- Звуки включаются пользовательским действием; есть сохраняемая кнопка mute. Звуковые эффекты не воспроизводятся в скрытой вкладке.
- Рекорды и постоянный прогресс записываются сразу после действия локально и через SDK player data / safe storage. Партия (монеты, улучшения, жизни, комбо, контейнеры) дополнительно сохраняется локально и восстанавливается на паузе; позиции предметов/незавершённые полёты не восстанавливаются, лента начинается заново. Удалённые записи сериализованы и объединяются, не чаще одной за 5 секунд; при ошибке сохраняется локальная копия.
- Русский и английский интерфейс; автоматический выбор языка через SDK, сохранение ручного выбора.
- Управление мышью/тачем, подавление контекстного меню и выделения на Canvas, в окне прогресса и на его кнопке.
- Локальные игровые ресурсы; production-архив не должен содержать `node_modules`, исходники инструментов, файлы Git или SDK-заглушку.

## Обязательная проверка в консоли перед отправкой на модерацию

1. Собрать `npm run build`. Упаковать **содержимое `dist`**, чтобы `index.html` находился в корне ZIP. Загрузить новую версию в консоль разработчика.
2. Запустить тестовую ссылку платформы и пройти её SDK-проверку: загрузка без ошибок, Ready после готовности первого экрана, Start только во время игры, Stop при меню/паузе/конце/рекламе.
3. Проверить настоящую rewarded-рекламу: просмотр до конца, закрытие без награды, отсутствие рекламы/ошибка, сворачивание вкладки во время показа. Награда ровно одна, игра и звук не возобновляются в фоне.
4. Проверить реальные cloud saves под авторизованным аккаунтом, перезапуск, новое устройство, игру без авторизации и временную потерю сети. Локальный тест со stub SDK не подтверждает доступность облака в конкретной публикации.
5. Проверить RU/EN из окружения SDK, все заявленные устройства, смену ориентации, перетаскивание пальцем, отсутствие перекрытых элементов и обрезанного текста. Особенно проверить небольшие экраны и браузеры iOS/Android.
6. Заполнить карточку: понятные название/описание/управление, соответствующие игре скриншоты и иконки, языки и поддерживаемые устройства, категория, возрастная маркировка и сведения о рекламе. Не обещать отсутствующие функции. Убедиться в правах на все материалы.
7. Проверить все актуальные требования по официальным ссылкам ниже; исправить замечания тестера/модерации. Одного локального билда недостаточно для заявления о полном соответствии.

## Автоматическая проверка SDK-адаптера

`CHROMIUM_PATH=/usr/lib/chromium/chromium npx playwright test tests/yandex.spec.ts` — **8 тестов прошли** на Chromium со stub SDK:

- Ready на стартовом меню без преждевременного Start; пауза платформы блокирует новый Start.
- Закрытие/ошибка рекламы и поздний callback не дают награду; успешный `onRewarded` даёт награду.
- Удалённые сохранения идут последовательно, промежуточные версии объединяются, локальная копия пишется сразу.
- При недоступности player data используется SDK storage, включая восстановление постоянного прогресса.
- Предложение джекпота останавливает GameplayAPI; таймаут возобновляет его, платформенная пауза запрещает перезапуск партии.

Эти тесты подтверждают поведение адаптера, но не настоящий рекламный инвентарь, сетевой доступ или настройки конкретного приложения Яндекс Игр.

## Проверка игрового цикла и сборки

- `npm test`: 15 тестов — награды, миграция, повреждённые данные, объединение сохранений, граница UTC-дня, уровни и границы автоматической сложности/времени реакции.
- `CHROMIUM_PATH=/usr/lib/chromium/chromium npm run test:e2e`: 38 браузерных тестов — 8 игрового цикла/интерфейса, 6 сохранений/паузы, 7 размеров поля/подписей, 8 SDK-адаптера, 7 fullscreen и 2 автоматической сложности.
- Проверены реальное перетаскивание мышью, пауза, покупка улучшения, неверный/полный контейнер, джекпот, конец партии и перезапуск, сохранение после reload, отсутствие XP за автосорт.
- Размеры 320×568, 390×844, 844×390, 1280×720: стартовое окно, клавиатурное закрытие, геометрия игрового поля с шестью типами и рекламной кнопкой.
- `npm run build`: TypeScript и production-сборка проходят. Production отдельно запущен через статический HTTP-сервер: реальное управление указателем, покупка улучшения, 26 сортировок и переход на смену 2 без JavaScript-исключений; дополнительно снят мобильный прогон. В compiled AdService ветка mock отключена.
- Сенсорный ввод проверен в эмуляции Chromium; физические устройства и Safari требуют отдельного прохода.

**Статус:** официальные требования сверены онлайн, найденные воспроизводимые недочёты исправлены. Сборка подготовлена для тестовой загрузки. Реальная платформа, настройки публикации и итоговое решение модерации пока не проверены.
