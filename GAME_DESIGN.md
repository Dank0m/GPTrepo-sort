# Sort & Upgrade — Game Design Document

Источник истины для требований. Реализация идёт по фазам из `TODO.md`.  
Фаза 0 — только технический фундамент. Игровые системы в этой фазе не реализуются.

## 1. Концепция

**Sort & Upgrade** — браузерная 2D-игра про сортировку предметов и прокачку линии.

Игрок встречает смешанный поток предметов, раскладывает их по подходящим контейнерам, зарабатывает монеты и тратит их на апгрейды. Апгрейды увеличивают скорость, ёмкость и автоматизацию, чтобы справляться с растущим потоком.

Жанр: casual / incremental sorting.  
Платформа: браузер (desktop + mobile).  
Управление: мышь / тач (начиная с фазы взаимодействия).  
Перспектива: 2D сверху / вид на стол и ленту.

## 2. Технические ограничения

- HTML5 Canvas 2D, без игрового движка.
- TypeScript, сборка Vite.
- Один полноэкранный canvas на весь viewport.
- Canvas обязан подстраиваться под размер окна и `devicePixelRatio`.
- Игровой цикл: `requestAnimationFrame`, `update(dt)` + `render()`.
- Без бэкенда, без аккаунтов, без базы данных в MVP.

## 3. Целевой опыт

Игрок должен быстро понять правило «предмет → свой контейнер», почувствовать ритм сортировки и увидеть, что апгрейды меняют темп. Сессия начинается за несколько секунд: предметы появляются, сортировка даёт монеты, монеты открывают апгрейды.

## 4. Основной цикл

1. Предметы появляются и движутся по линии.
2. Игрок сортирует предмет в контейнер своего типа.
3. Верная сортировка даёт монеты (и комбо при серии).
4. Ошибка тратит жизнь / снижает комбо (конкретные штрафы — в фазе экономики).
5. Монеты тратятся на апгрейды.
6. Поток ускоряется и усложняется.

## 5. Игровые объекты (не в PHASE 0)

- **Предмет** — тип (цвет/форма), позиция на ленте, состояние (на ленте / в руке / в контейнере).
- **Контейнер** — принимает один тип, имеет ёмкость.
- **Лента** — движет предметы **слева направо**. Направление зафиксировано в PHASE 1.
- **Монеты** — валюта апгрейдов.
- **Апгрейд** — пассивный эффект: скорость ленты, ценность предмета, автосорт, доп. контейнер.

## 6. Управление (не в PHASE 0)

- Desktop: захват предмета мышью, перетаскивание в контейнер.
- Mobile: тот же жест тачем.
- Клик по кнопке апгрейда в HUD.

## 7. Экономика и апгрейды (не в PHASE 0)

Базовая валюта: монеты за верную сортировку.  
Апгрейды покупаются сразу, действуют до конца сессии (престиж — за рамками MVP).

Планируемый набор MVP:

- скорость ленты;
- ценность предмета;
- дополнительный контейнер / тип;
- автосортировщик (медленный, неполный);
- размер буфера на ленте.

Точные числа балансируются после появления прототипа сортировки.

PHASE 3 (зафиксировано после прототипа сортировки):

- верный дроп: `10 × комбо` монет, комбо растёт с 1;
- ошибка (неверный контейнер) или съезд с ленты: комбо = 0, −1 жизнь;
- старт: 3 жизни;
- полный контейнер: предмет возвращается на ленту без штрафа.

PHASE 4 (магазин, до конца сессии):

- Скорость: +40 px/s к ленте и чуть чаще спавн, цены 30 / 60 / 120 / 240;
- Ценность: +10 к базовым монетам за уровень, 40 / 80 / 160;
- Тип: до трёх новых контейнеров — зелёный ромб, фиолетовая звезда, оранжевый гекс. Цены 80 / 160 / 320;
- Когда **все** контейнеры полные: буфер (заполнение) обнуляется, джекпот `120 × N²` монет (N — число типов), анимация «Полный набор»;
- Автосорт: кладёт **самый правый** предмет на ленте в свой контейнер (тот, что ближе к съезду; позиция после перестановки игроком), 50 / 100 / 200;
- Буфер: больше зазор между предметами, 25 / 50 / 100.

## 8. UI

PHASE 0: только canvas, заголовок, debug overlay (FPS, размер, DPR, номер фазы).  
PHASE 1: лента, предметы смешанного потока, контейнеры по типам. Без HUD экономики.  
PHASE 2: захват мышью/тачем, дроп в контейнер своего типа. Монет и комбо нет.  
PHASE 3: монеты за верный дроп, комбо, жизни. Предмет за краем ленты — промах. Апгрейдов нет.  
PHASE 4: магазин апгрейдов внизу экрана. Покупки на сессию.  
PHASE 5: читаемый HUD, частицы и всплывающий текст, звуки Web Audio (выключаются кнопкой), подсказка в начале, «полно» / «мимо» / конец сессии, магазин в две строки на узком экране. Debug overlay по клавише D.  
PHASE 6: пауза (кнопка, Esc/P, сворачивание вкладки), звук глушится без фокуса, рекорд монет и комбо в localStorage, «Новый рекорд» на конце сессии. Long-press не открывает меню браузера.  
PHASE 7: опциональная rewarded-реклама через `AdService` / `YandexService`, облачный сейв рекорда, игра без SDK в fallback.

Позже: счётчик монет, кнопки апгрейдов, индикатор комбо, жизни / переполнение ленты.

## 9. Вне скоупа (пока не делаем)

- Онлайн-мультиплеер, аккаунты кроме Яндекс ID через SDK.
- 3D, WebGL, физический движок.
- Сюжет, диалоги, карта мира.
- Инап-покупки (IAP).
- Полноэкранная interstitial в Phase 7 не показывается игроку (только метод-заглушка в `YandexService`). Rewarded — опционально, см. Phase 7.

## 10. Фазы реализации

| Фаза | Содержание |
| --- | --- |
| **0** | Проект, TypeScript, Canvas, цикл, ресайз, запуск. Без механик. |
| 1 | Предметы, лента, контейнеры как отображаемые объекты. |
| 2 | Ввод: захват и сортировка. |
| 3 | Очки, ошибки, комбо. |
| 4 | Апгрейды и трата монет. |
| 5 | UI, полировка, звук по возможности. |
| 6 | Пауза, рекорды, звук без фокуса. |

PHASE 0 считается завершённой, когда проект запускается локально, canvas заполняет окно и подстраивается при изменении размера, игровых механик нет.

# 11. PHASE 7 — SDK, rewarded ads, cloud save

Реализация: `src/services/YandexService.ts`, `src/services/AdService.ts`. Игровой код не импортирует `YaGames`.

В конвейере нет уровней. Маппинг из типичного sort-GDD:

| Формулировка GDD | В этой игре |
| --- | --- |
| После проигрыша / ошибки → CONTINUE? | Только **game over** (жизни = 0). Не каждый промах. |
| После уровня → DOUBLE REWARD | После **полного набора** (дамп, джекпот). |
| FREE COINS | Слот в магазине / HUD во время сессии. |

## 11.1 Принципы рекламы

- Реклама **опциональна**. Игрок сам нажимает «посмотреть». Нет автопоказа, нет таймера «каждые N секунд», нет ролика на каждый неверный дроп.
- Только **rewarded video**. Interstitial в Phase 7 из геймплея **не вызывается** (метод есть в `YandexService` как заглушка на будущее).
- Кнопка всегда говорит две вещи: будет реклама и какая награда. Пример: `CONTINUE?  Реклама → +1 жизнь`.
- Награда только после успешного `onRewarded`. Закрыл ролик раньше / ошибка SDK / нет рекламы → **ноль** монет и жизней.
- На время ролика: мир на паузе, звук выключен, `GameplayAPI.stop()`. После `onClose`: снять паузу, если сессия жива; иначе оставить game over. `GameplayAPI.start()` только если снова играем.
- В один момент на экране не больше одной «в лицо» rewarded-кнопки. Free coins живёт в магазине, не стопкой на game over вместе с Continue.

## 11.2 Места rewarded

### A. CONTINUE? — конец сессии

После game over, рядом с «Заново»:

```
CONTINUE?
Посмотреть рекламу → +1 жизнь
сессия продолжается
```

Поток:

1. Жизни дошли до 0, мир в статусе `gameOver`, лента стоит.
2. Если `AdService.canShow("continue")` — рисуем кнопку Continue.
3. Успешный ролик → жизни = **1** (не полный набор из 3), статус снова `playing`, всё остальное **как было**: монеты, апгрейды, заполнение контейнеров, предметы на ленте.
4. Флаг `continueUsedThisSession = true`. Следующий game over в этой сессии — только «Заново».
5. «Заново» / отказ / skip / unavailable → `restart()`, как сейчас.

Лимит: **один Continue на сессию**.

### B. DOUBLE REWARD — после полного набора

Сразу после джекпота «ПОЛНЫЙ НАБОР»:

```
DOUBLE REWARD
Посмотреть рекламу → джекпот ещё раз
```

Поток:

1. Все контейнеры полные → дамп, базовый джекпот **уже начислен** (`120 × N²`).
2. Короткий оверлей (~5 с) с кнопкой «Удвоить (реклама)» и «Нет» / авто-закрытие.
3. Успешный ролик → начислить **ещё раз ту же сумму** (итого ×2 к этой выплате, не к балансу целиком).
4. Один оффер на этот дамп. Следующий полный набор — новый оффер.
5. Игра не стопается навсегда: таймаут или «Нет» → оверлей снимается, лента едет.

Лимит: **один дабл на каждый дамп**.

### C. FREE COINS — бонус в магазине

Слот в ряду апгрейдов (или рядом с HUD):

```
FREE COINS
Посмотреть рекламу
+500 🪙
```

Поток:

1. Доступна во время `playing`, если `canShow("freeCoins")`.
2. Успешный ролик → `coins += 500`, старт кулдауна **90 с**.
3. Пока кулдаун: слот показывает оставшиеся секунды, нажать нельзя.
4. Fallback / нет SDK: слот **скрыт**. Нельзя выдать 500 «просто так».

Награда не нужна, чтобы купить апгрейды или закрыть сессию.

**Не делать:** rewarded на каждый промах, на каждый верный дроп, на старт сессии.

## 11.3 Архитектура

Игровой код (`World`, HUD, сцена, магазин) **не импортирует** `YaGames` и не знает про `ysdk.adv`.

```
World / HUD / Shop
        │
        ├── AdService                 цели: continue | dumpDouble | freeCoins
        │         │
        │         └── YandexService   единственный вызов Яндекс API
        │
        └── save (рекорд)
                  └── YandexService.saveGame / loadGame
                      └── localStorage как всегда + облако, если SDK есть
```

Файлы (когда начнём код):

- `src/services/YandexService.ts`
- `src/services/AdService.ts`
- `index.html`: `<script src="/sdk.js">` (на localhost файла может не быть — это нормально)

### `YandexService`

Единственное место с Яндекс API. Остальной код зовёт только эти методы:

```
YandexService.init()
YandexService.ready()
YandexService.gameplayStart()
YandexService.gameplayStop()
YandexService.showRewardedAd()
YandexService.showInterstitial()
YandexService.saveGame(data)
YandexService.loadGame()
YandexService.getLanguage()
```

| Метод | Что делает |
| --- | --- |
| `init()` | Если нет `YaGames` — попытка загрузить `/sdk.js`, затем `YaGames.init()`. Резолвится всегда. Поле `available`. |
| `ready()` | `LoadingAPI.ready()` когда канвас уже играбелен. No-op без SDK. |
| `gameplayStart()` / `gameplayStop()` | Пауза, game over, реклама, скрытие вкладки. No-op без SDK. |
| `showRewardedAd()` | `adv.showRewardedVideo` → `{ rewarded: boolean }`. Без SDK: `{ rewarded: false }`. |
| `showInterstitial()` | `adv.showFullscreenAdv`. **В Phase 7 из игры не зовётся.** |
| `saveGame(data)` / `loadGame()` | Авторизованный игрок: `player.setData` / `getData`. Гость: `ysdk.getStorage()` если есть, иначе `localStorage`. |
| `getLanguage()` | `environment.i18n.lang`, иначе `"ru"`. |
| achievements | Пустые методы-заглушки. Консоль ачивок не делаем. |

Тип сейва Phase 7 — тот же, что сейчас в `localStorage`:

```
{ bestCoins, bestCombo, gamesPlayed }
```

Пишем в облако после game over и после успешной награды. Локальный ключ `sortup-records` остаётся источником на localhost.

### `AdService`

То, что видит игра. Не Яндекс API, а цели.

```
AdService.canShow(goal): boolean
AdService.show(goal): Promise<"rewarded" | "skipped" | "unavailable">
```

`goal`: `"continue" | "dumpDouble" | "freeCoins"`.

Внутри `show`:

1. Пауза мира, mute, `YandexService.gameplayStop()`.
2. `YandexService.showRewardedAd()`.
3. По `onClose`: unmute, resume если сессия жива, `gameplayStart()` если играем.
4. Вернуть статус. Награду начисляет **игра** (жизнь / монеты), не сервис.

**Запрещено** в fallback выдавать награду так, будто ролик просмотрен. Исключение только `?mockAds=1` для локальной отладки, не для продакшен-архива.

## 11.4 Fallback (SDK нет)

Локальный `npm run preview` без `/sdk.js`:

- Игра запускается как Phase 6.
- Кнопки Continue / Double / Free coins **не показываются**.
- Рекорд как сейчас: только `localStorage`.
- `LoadingAPI` / `GameplayAPI` / `adv` не вызываются (ранний return в `YandexService`).
- Нет сетевых ошибок в консоли, из-за которых ломается цикл.

Это обязательное требование: без Яндекса игра должна работать.

## 11.5 UI (канвас)

- Game over: «Продолжить (реклама) +1 жизнь» + «Заново».
- Оверлей дампа: «Удвоить (реклама)» ~5 с + «Нет».
- Магазин: слот Free coins; на кулдауне — таймер.
- Пока крутится ролик — оверлей «Реклама…», мир на паузе. Плеер рисует платформа поверх канваса.

Копирайт кнопок на русском и английском (`src/i18n`). Переключение — кнопка с флагами в HUD. Старт: сохранённый выбор, иначе `getLanguage()` / `navigator.language` (не `en` → русский).

## 11.6 Вне скоупа Phase 7

- Interstitial в геймплее (старт, между «уровнями», после N дропов).
- IAP, магазин Яндекса.
- Ачивки в консоли (только пустые методы).
- Принудительный просмотр, rewarded на промах.
- Фейковые награды без ролика.

## 11.7 Критерий готовности

- Локально без SDK — как Phase 6, ничего не сломано.
- С debug-панелью Яндекса: `init` + `LoadingAPI.ready`, rewarded на трёх местах с понятной наградой.
- Пауза и mute на ролике; отказ / skip не ломает сессию и не даёт награду.
- Рекорд уезжает в player data, если SDK есть.
- `World` / HUD не содержат слова `YaGames`.
