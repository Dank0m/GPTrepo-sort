# SORT & UPGRADE
## Game Design Document / Техническое задание для разработки

### 1. Общая информация

**Рабочее название:** Sort & Upgrade  
**Жанр:** Casual Puzzle + Upgrade / Progression  
**Платформа:** Яндекс Игры  
**Ориентация:** Portrait (вертикальная)  
**Основные устройства:** мобильные, планшеты, desktop  
**Технологии:** HTML5 + JavaScript/TypeScript + Canvas  
**Основная цель:** создать простую игру с очень низким порогом входа, короткими игровыми сессиями и постоянной прогрессией.

---

# 2. Концепция

Игрок сортирует предметы по соответствующим контейнерам.

Пример:

```
        🍎 🟡 🍎 🔵 🟡

      ┌─────┐ ┌─────┐ ┌─────┐
      │  🍎 │ │  🟡 │ │  🔵 │
      └─────┘ └─────┘ └─────┘
```

Игрок перетаскивает каждый предмет в правильный контейнер.

За правильно отсортированные предметы игрок получает монеты.

Монеты используются для улучшения различных характеристик.

Главная игровая петля:

```
Сортировка
     ↓
Награда
     ↓
Монеты
     ↓
Upgrade
     ↓
Более сложная сортировка
     ↓
Больше наград
     ↓
Новые Upgrade
     ↓
...
```

Игра должна быть понятна без объяснения практически сразу после запуска.

---

# 3. Главные принципы

При разработке соблюдать следующие приоритеты:

1. Простота.
2. Быстрый старт.
3. Минимум текста.
4. Приятная анимация.
5. Постоянное ощущение прогресса.
6. Короткие игровые сессии.
7. Возможность легко добавлять новые уровни.
8. Хорошая работа на мобильных устройствах.
9. Быстрая загрузка.
10. Архитектура должна позволять масштабировать игру без переписывания ядра.

Не создавать сложные системы, если они не улучшают gameplay.

# 5. Основная механика сортировки

Каждый уровень содержит:

- N предметов;
- N типов предметов;
- N контейнеров.

Каждый предмет имеет `typeId`.

Каждый контейнер связан с определённым `typeId`.

Игрок может:

- нажать/зажать предмет;
- перетащить его;
- отпустить над контейнером.

Если предмет помещён в правильный контейнер:

- предмет исчезает или красиво перемещается внутрь;
- начисляется награда;
- проигрывается короткая анимация;
- проигрывается звук;
- обновляется прогресс.

Если предмет помещён неправильно:

- предмет возвращается назад;
- проигрывается небольшая анимация ошибки;
- не снимаются монеты;
- уровень не перезапускается.

# 6. Управление

Игра должна поддерживать:

### Mobile

Touch / pointer events.

### Desktop

Mouse / pointer events.

Не использовать отдельные реализации для mouse и touch.

Использовать единую Pointer Events систему.

Основное действие:

```
pointerdown
    ↓
drag
    ↓
pointerup
```

Предмет должен следовать за пальцем/курсором с небольшим визуальным offset.

---

# 7. Уровни

Уровни должны генерироваться процедурно.

Не создавать вручную сотни уровней.

Каждый уровень имеет параметры:

```ts
interface LevelConfig {
    level: number;
    itemTypes: number;
    itemsPerType: number;
    shuffleAmount: number;
    difficulty: number;
    rewardMultiplier: number;
}
```

---

# 8. Прогрессия сложности

Первые уровни должны быть очень простыми.

### Levels 1–5

- 2 типа предметов;
- 2 контейнера;
- небольшое количество предметов;
- минимум хаоса.

### Levels 6–15

- 3 типа;
- больше предметов;
- больше расстояние между предметами.

### Levels 16–30

- 4 типа;
- больше предметов;
- более сложное расположение.

### Levels 31–50

- 5 типов;
- больше объектов;
- специальные препятствия.

### 50+

Постепенно увеличивать сложность.

Не делать резких скачков сложности.

---

# 9. Типы предметов

Для MVP использовать простые геометрические формы.

Не зависеть от внешних изображений.

Примеры:

- circle;
- square;
- triangle;
- diamond;
- star.

Каждый тип должен иметь уникальный внешний вид.

В дальнейшем предметы можно заменить на:

- фрукты;
- животных;
- драгоценности;
- игрушки;
- еду;
- космические объекты.

Архитектура не должна зависеть от конкретной тематики.

---

# 10. Генератор уровней

Уровень должен создаваться на основании seed.

Пример:

```ts
generateLevel(levelNumber, seed)
```

Одинаковый seed должен давать одинаковый уровень.

Это необходимо для:

- отладки;
- повторяемости;
- тестирования;
- возможного добавления daily challenge.

Генератор должен гарантировать, что каждый уровень проходим.

---

# 11. Экономика

Основная валюта:

## Coins 🪙

Игрок получает монеты за:

- правильную сортировку;
- завершение уровня;
- streak/combo;
- выполнение ежедневных заданий;
- просмотр rewarded-рекламы.

---

# 12. Формула награды

Базовая награда:

```text
baseReward = numberOfItems × 10
```

Финальная награда:

```text
reward =
baseReward
× levelMultiplier
× comboMultiplier
× upgradeMultiplier
```

Не допускать слишком быстрого роста экономики.

Все коэффициенты вынести в отдельный конфигурационный файл.

---

# 13. Combo

Если игрок быстро выполняет несколько правильных действий подряд:

```
COMBO x2
COMBO x3
COMBO x4
...
```

Combo сбрасывается при ошибке или после длительной паузы.

Combo должно быть визуально заметным, но не мешать gameplay.

---

# 14. Upgrade System

Главная метаигра.

После прохождения уровня игрок получает возможность улучшать характеристики.

Минимум 3 upgrade:

### 1. Reward

Увеличивает количество получаемых монет.

```
Reward Level 1
+10%

Reward Level 2
+20%

Reward Level 3
+30%
```

### 2. Combo

Увеличивает бонус от combo.

### 3. Speed

Ускоряет визуальное перемещение предметов и/или даёт небольшой бонус к награде за быстрое прохождение.

---

# 15. Стоимость Upgrade

Стоимость должна расти экспоненциально.

Пример:

```text
cost = baseCost × growthRate ^ upgradeLevel
```

Например:

```text
baseCost = 100
growthRate = 1.55
```

Все значения должны находиться в конфигурации.

# 17. Постоянный прогресс

Прогресс должен сохраняться между запусками.

Сохранять:

```ts
interface SaveData {
    version: number;
    level: number;
    coins: number;

    upgrades: {
        reward: number;
        combo: number;
        speed: number;
    };

    totalLevelsCompleted: number;
    bestCombo: number;

    settings: {
        sound: boolean;
        music: boolean;
    };
}
```

Использовать localStorage для MVP.

Архитектура должна позволять позже заменить storage на Яндекс Games Cloud Save.

Добавить ежедневный streak.

Например:

```

```

Система должна быть простой и не требовать аккаунта.

---

# 20. Rewarded Advertising

Реклама должна быть опциональной.

Основные места:

### После проигрыша / ошибки

```
CONTINUE?

Watch ad
```

### После уровня

```
DOUBLE REWARD

Watch ad → x2 coins
```

### Бесплатный бонус

Например:

```
FREE COINS

Watch ad
+500 🪙
```

Не заставлять пользователя смотреть рекламу постоянно.

Rewarded video всегда должен давать понятную награду.

Интеграцию рекламы вынести в отдельный сервис:

```ts
AdService
```

Игровой код не должен напрямую зависеть от API Яндекс Игр.

---

# 21. Interstitial Advertising

Interstitial показывать только в естественных паузах.

Например после нескольких завершённых уровней.

Не показывать рекламу:

- во время drag;
- во время gameplay;
- сразу после запуска;
- слишком часто;
- после каждого действия.

Интервал между interstitial должен задаваться конфигурацией.

---

# 22. Яндекс Games SDK

Создать отдельный слой:

```ts
YandexService
```

Он отвечает за:

- инициализацию SDK;
- рекламу;
- cloud save;
- player data;
- achievements при необходимости.

Остальной код игры не должен напрямую вызывать Yandex API.

Пример:

```ts
YandexService.showRewardedAd()
YandexService.showInterstitial()
YandexService.saveGame(data)
YandexService.loadGame()
```

Если SDK недоступен, игра должна работать в fallback-режиме.

# 23. UI / UX

Главный принцип:

## игрок должен понимать игру без чтения длинных инструкций.

При первом запуске:

1. Показать предмет.
2. Показать контейнер.
3. Анимировать правильное перетаскивание.
4. Предложить игроку повторить действие.

Tutorial должен занимать максимум несколько секунд.

Не использовать длинные текстовые окна.

**Clean / Colorful / Soft Casual**

# 28. Performance

Цель:

- быстрый запуск;
- минимум загрузок;
- стабильные 60 FPS;
- отсутствие лагов при drag.

Минимизировать:

- количество DOM элементов;
- количество изображений;
- размер JavaScript bundle;
- количество сетевых запросов.

# 30. Game State

Использовать конечный автомат.

Минимальные состояния:

```ts
enum GameState {
    Loading,
    Tutorial,
    Playing,
    LevelComplete,
    Upgrade,
    Paused
}
```

Не допускать ситуации, когда несколько экранов одновременно считают себя активными.

---

# 31. Конфигурация

Все параметры баланса должны быть вынесены из игрового кода.

Например:

```ts
export const BALANCE = {
    baseReward: 10,

    upgrade: {
        baseCost: 100,
        growthRate: 1.55
    },

    combo: {
        maxMultiplier: 10
    },

    ads: {
        minInterstitialLevelInterval: 3
    }
};
```

Это позволит быстро менять баланс без изменения игровой логики.

# 36. Правила для AI-разработчика

При разработке:

### Правило 1

Не переписывать архитектуру без необходимости.

### Правило 2

Не добавлять функциональность, которой нет в этом документе, без явной необходимости.

### Правило 3

Если требуется выбрать между двумя решениями, выбирать более простое.

### Правило 4

Сначала реализовывать работающий MVP, затем polish.

### Правило 5

Не использовать placeholder TODO вместо работающего кода.

### Правило 6

Каждая игровая система должна быть максимально независимой.

### Правило 7

Баланс не должен быть захардкожен внутри gameplay-кода.
