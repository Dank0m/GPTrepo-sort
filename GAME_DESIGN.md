# Sort & Upgrade — Game Design Document

Источник истины для требований. Реализация идёт по фазам из `TODO.md`.  
Фаза 0 — только технический фундамент. Игровые системы в этой фазе не реализуются.

## 1. Концепция

**Sort & Upgrade** — браузерная 2D-игра про сортировку предметов и прокачку линии.

Игрок встречает смешанный поток предметов, раскладывает их по подходящим контейнерам, зарабатывает монеты и тратит их на апгрейды. Апгрейды увеличивают скорость, ёмкость и автоматизацию, чтобы справляться с растущим потоком.

Жанр: casual / incremental sorting.  
Платформа: браузер (desktop + mobile).  
Управление: мышь / тач (начиная с фазы взаимодействия).  
Перспектива: 2D сверху / вид на стол и ленту.

## 2. Технические ограничения

- HTML5 Canvas 2D, без игрового движка.
- TypeScript, сборка Vite.
- Один полноэкранный canvas на весь viewport.
- Canvas обязан подстраиваться под размер окна и `devicePixelRatio`.
- Игровой цикл: `requestAnimationFrame`, `update(dt)` + `render()`.
- Без бэкенда, без аккаунтов, без базы данных в MVP.

## 3. Целевой опыт

Игрок должен быстро понять правило «предмет → свой контейнер», почувствовать ритм сортировки и увидеть, что апгрейды меняют темп. Сессия начинается за несколько секунд: предметы появляются, сортировка даёт монеты, монеты открывают апгрейды.

## 4. Основной цикл

1. Предметы появляются и движутся по линии.
2. Игрок сортирует предмет в контейнер своего типа.
3. Верная сортировка даёт монеты (и комбо при серии).
4. Ошибка тратит жизнь / снижает комбо (конкретные штрафы — в фазе экономики).
5. Монеты тратятся на апгрейды.
6. Поток ускоряется и усложняется.

## 5. Игровые объекты (не в PHASE 0)

- **Предмет** — тип (цвет/форма), позиция на ленте, состояние (на ленте / в руке / в контейнере).
- **Контейнер** — принимает один тип, имеет ёмкость.
- **Лента** — движет предметы **слева направо**. Направление зафиксировано в PHASE 1.
- **Монеты** — валюта апгрейдов.
- **Апгрейд** — пассивный эффект: скорость ленты, ценность предмета, автосорт, доп. контейнер.

## 6. Управление (не в PHASE 0)

- Desktop: захват предмета мышью, перетаскивание в контейнер.
- Mobile: тот же жест тачем.
- Клик по кнопке апгрейда в HUD.

## 7. Экономика и апгрейды (не в PHASE 0)

Базовая валюта: монеты за верную сортировку.  
Апгрейды покупаются сразу, действуют до конца сессии (престиж — за рамками MVP).

Планируемый набор MVP:

- скорость ленты;
- ценность предмета;
- дополнительный контейнер / тип;
- автосортировщик (медленный, неполный);
- размер буфера на ленте.

Точные числа балансируются после появления прототипа сортировки.

## 8. UI

PHASE 0: только canvas, заголовок, debug overlay (FPS, размер, DPR, номер фазы).  
PHASE 1: лента, предметы смешанного потока, контейнеры по типам. Без HUD экономики.

Позже: счётчик монет, кнопки апгрейдов, индикатор комбо, жизни / переполнение ленты.

## 9. Вне скоупа MVP

- Онлайн, аккаунты, лидерборды.
- 3D, WebGL, физический движок.
- Сюжет, диалоги, карта мира.
- Реклама и IAP.

## 10. Фазы реализации

| Фаза | Содержание |
| --- | --- |
| **0** | Проект, TypeScript, Canvas, цикл, ресайз, запуск. Без механик. |
| 1 | Предметы, лента, контейнеры как отображаемые объекты. |
| 2 | Ввод: захват и сортировка. |
| 3 | Очки, ошибки, комбо. |
| 4 | Апгрейды и трата монет. |
| 5 | UI, полировка, звук по возможности. |

PHASE 0 считается завершённой, когда проект запускается локально, canvas заполняет окно и подстраивается при изменении размера, игровых механик нет.
